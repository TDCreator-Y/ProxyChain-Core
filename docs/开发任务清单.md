# 🛠️ ProxyChain Core: 从 0 到 1 开发任务清单

本文档是指导 AI (Trae) 进行代码生成的执行手册。分为 6 个阶段，采用“底层先行，UI 后接，逐步联调”的策略。

## 阶段一：项目基础设施搭建 (Infrastructure)

本阶段目标：跑通 Flutter 与 Rust 的混合编译环境，证明跨语言调用链路畅通。

### 任务 1.1：初始化 Monorepo 与构建工具

**AI 开发提示词：**

```text
“你现在是一个资深的跨平台架构师。请帮我初始化一个 Flutter + Rust 的项目工程。

创建一个标准的 Flutter 项目作为宿主。

在项目根目录创建一个 Rust 工程 (cargo new core_rust --lib)。

请使用 flutter_rust_bridge (V2版本) 配置双向通信基础设施。

在 Rust 端编写一个 greet(name: String) -> String 的测试函数，并在 Flutter 端的 main.dart 中调用它并在屏幕中心显示返回值。”
```

**测试办法：** 在终端运行 `flutter run -d macos` (或 `windows/linux`)。

**预期测试结果：** 程序成功编译并启动，屏幕正中间显示来自 Rust 的字符串：“Hello, [Name] from Rust!”。

## 阶段二：核心数据结构与配置管理 (Data Models)

本阶段目标：定义节点、代理链和状态的强类型数据模型，确保前后端数据语言一致。

### 任务 2.1：定义节点与代理链数据结构

**AI 开发提示词：**

```text
“请在 core_rust 项目中，使用 serde 库定义代理节点的数据结构。
需要包含以下 Struct：

ProxyNode: 包含 id (String), name (String), protocol (枚举: Shadowsocks, Trojan, Socks5, Vmess), server (String), port (u16), password (String), cipher (Option)。

ProxyChain: 包含 entry_node (ProxyNode) 和 exit_node (ProxyNode)。
请确保这些结构体可以通过 flutter_rust_bridge 自动生成 Dart 侧的类。并写一个简单的 Rust 函数 create_mock_chain() -> ProxyChain 供前端测试。”
```

**测试办法：** 在 Flutter 代码中调用 `createMockChain()`，并使用 `print()` 打印出返回的 `exit_node` 的 `name`。

**预期测试结果：** 控制台成功打印出 Rust 端伪造的节点名称（例如："Mock ISP Node"），无序列化报错。

## 阶段三：Rust 核心代理逻辑 (Core Proxy Engine)

本阶段目标：实现最核心的双重代理转发链路（暂时不接管系统 TUN，先暴露本地 Socks5 端口进行测试）。

### 任务 3.1：搭建双节点 Relay 路由逻辑

**AI 开发提示词：**

```text
“现在需要实现核心的级联代理转发逻辑。请在 Rust 端引入 tokio 异步运行库。
编写一个函数 start_local_proxy(chain: ProxyChain, local_port: u16) -> Result<(), String>。
逻辑要求：

在本地启动一个 TCP 监听器（如 127.0.0.1:1080）。

当有流量接入时，首先与 chain.entry_node 建立加密连接。

核心：在建立好第一层连接的通道（Stream）上，继续向 chain.exit_node 发起连接请求。

成功后，将本地流量和这层嵌套的双层 Stream 进行 tokio::io::copy_bidirectional 流量双向拷贝。
暂时可以使用基础的 Socks5 协议作为测试桩。”
```

**测试办法：** 使用 Trae 编写一个单元测试，或直接在本地运行。使用命令行：`curl -x socks5h://127.0.0.1:1080 https://ifconfig.me`。

**预期测试结果：** `curl` 命令成功返回网页数据，并且返回的 IP 地址是 `exit_node` (出口 ISP 节点) 的 IP 地址，而不是本地或入口节点的 IP。

## 阶段四：Flutter 前端界面开发 (UI & State)

本阶段目标：不依赖真实后端逻辑，依靠 Mock 数据完成漂亮的界面交互。

### 任务 4.1：构建仪表盘与状态管理

**AI 开发提示词：**

```text
“请使用 Flutter 和 flutter_riverpod 构建主界面 (Dashboard)。

创建一个全局状态 vpnStateProvider (包含状态：Disconnected, Connecting, Connected)。

界面顶部放置一个巨大的圆形操作按钮，根据状态改变颜色（红/黄/绿）和图标。

按钮下方显示当前选中的代理链：左侧是入口节点名称，右侧是出口节点名称，中间用箭头 '->' 连接。

创建一个折线图组件（可以使用 fl_chart 库），预留接口用来接收 Stream<TrafficData> 以绘制实时网速。”
```

**测试办法：** 手动在 UI 上点击圆形按钮。

**预期测试结果：** 按钮颜色和文本按状态平滑过渡（支持动画）；占位的折线图正常渲染。

### 任务 4.2：构建双层节点选择器 (Chain Builder)

**AI 开发提示词：**

```text
“请编写‘链路构建器’页面。

页面分为左右两栏（或上下两个独立的可滑动列表区）。

区域一为 'Entry Pool'，区域二为 'Exit Pool'。

使用 ListView.builder 渲染节点卡片。卡片上显示国旗图标、节点名称和协议类型。

点击卡片时，更新 Riverpod 中的 selectedEntryNode 或 selectedExitNode 状态，并在 UI 上高亮显示当前选中的卡片。”
```

**测试办法：** 在两个列表中分别点击不同的节点卡片。

**预期测试结果：** 被点击的卡片出现边框或高亮背景色；切换回主面板时，主面板的“入口->出口”文字更新为刚才选中的节点。

## 阶段五：前后端联调与 TUN 流量接管 (Integration)

本阶段目标：将 UI 与底层真正的代理逻辑串联，并实现全局流量接管。

### 任务 5.1：打通启停逻辑与流量回传

**AI 开发提示词：**

```text
“请将 Flutter UI 的启停按钮与 Rust底层的代理逻辑串联。

在 Rust 端暴露异步接口 start_engine(entry_id: String, exit_id: String) -> anyhow::Result<()> 和 stop_engine()。

在 Rust 端使用通道 (mpsc) 持续统计上下行字节数，并通过 flutter_rust_bridge 的 StreamSink 每秒推送一次 TrafficStatus { up: u64, down: u64 } 给 Dart。

在 Flutter 侧监听这个 Stream，并将数据喂给 fl_chart 折线图组件更新实时网速。”
```

**测试办法：** 在应用中点击“连接”按钮，打开浏览器看视频或下载大文件。

**预期测试结果：** 软件提示连接成功；UI 上的网速图表开始产生波浪形的数据波动，数值大小与实际下载速度基本吻合。

### 任务 5.2：(桌面端) 开启 TUN 虚拟网卡接管

**AI 开发提示词：**

```text
“请在 Rust 核心中集成 TUN 虚拟网卡功能以实现全局路由接管。

推荐使用现成的 crate（如 tun 或从 shadowsocks-rust 中剥离的 tun 模块）。

启动代理时，创建一个名为 proxy_tun0 的虚拟网卡，设置 IP 为 198.18.0.1/15。

自动修改系统的路由表，将全局默认网关指向该 TUN 接口，原有的物理网关路由设置为只允许发往 entry_node 的流量通过（防止路由环路死循环）。

读取 TUN 的原始 IP 数据包（IPv4/IPv6），进行 TCP/UDP 还原，然后喂入我们阶段三写好的 Relay 转发引擎中。”
```

**测试办法：** 打开软件全局连接。关闭浏览器的所有代理插件，直接在浏览器中访问 `youtube.com` 或 `ipinfo.io`。

**预期测试结果：** 所有软件（甚至包括命令行工具，如 `ping google.com`）的流量全部自动走了代理链，IP 均显示为固定的 ISP IP 地址。

## 阶段六：订阅解析与持久化 (Subscriptions)

本阶段目标：让软件能够动态获取节点，并保存用户的配置，下次打开不用重新设置。

### 任务 6.1：订阅拉取与 YAML/Base64 解析

**AI 开发提示词：**

```text
“在 Rust 端实现一个订阅更新引擎。

暴露函数 fetch_subscription(url: String) -> Result<Vec<ProxyNode>, String>。

使用 reqwest 库发起 GET 请求获取订阅内容。

自动识别内容是 Base64 还是 YAML（如 Clash 格式）。

解析文本内容，生成 ProxyNode 列表并返回给前端。”
```

**测试办法：** 在 UI 输入一个合法的机场订阅链接，点击“更新”。

**预期测试结果：** 短暂 Loading 后，UI 的 Entry Pool 列表中自动填充了几十个带有国家名称的节点。

### 任务 6.2：配置本地持久化

**AI 开发提示词：**

```text
“请实现本地配置的保存功能。
我们需要在每次修改了订阅链接、或者切换了选中的代理节点后，把状态保存到本地磁盘。

在 Flutter 端，引入 shared_preferences 或 isar 数据库。

编写一个 ConfigManager 服务，负责将当前的 ProxyChain 状态（入口id，出口id，已添加的出口节点列表）序列化为 JSON 保存。

在 App 启动时，优先读取该配置并还原 UI 状态。”
```

**测试办法：** 选择一个 VPN 节点和 ISP 节点，关闭程序，重新打开程序。

**预期测试结果：** 程序启动后，UI 直接显示上次关闭前选择的两个节点，数据未丢失。

## 阶段七：打包与发布准备 (Release)

### 任务 7.1：Release 构建与系统权限清单

**AI 开发提示词：**

```text
“我们要准备打包应用的 Release 版本了。

请帮我检查 macOS 的 Info.plist 和 Windows 的 app.manifest，确保我们声明了需要获取管理员权限（因为创建 TUN 网卡需要）。

帮我写一个用于自动化构建全平台 Release 产物的 Shell / CI 脚本。”
```

**测试办法：** 运行构建脚本，获取 `.dmg` 或 `.exe` 安装包，在另一台全新的电脑上安装运行。

**预期测试结果：** 独立安装包正常运行，且首次点击连接时，系统会弹出原生权限认证弹窗要求输入管理员密码，输入后连接成功。
